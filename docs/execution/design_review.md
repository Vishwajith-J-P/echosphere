# Current limitations and design review

## Basis and limits of review

Reviewed 2026-09-05 against the local Flask routes, settings, session service, Agora gateway, React API/media hook/page, backend tests, Vite configuration, and documented API/schema/safety contracts. This is a static review: races below are derived from execution ordering, not reproduced in a live Agora call. No credentials were inspected, providers called, benchmarks run, or application files changed. Findings are proposals for implementation, not accepted migrations or completed fixes. No finite review establishes that every possible defect has been found.

Evidence paths below are relative to the repository root. P0 blocks a credible safety/handoff demonstration; P1 blocks reliable end-to-end prototype completion; P2 is required before broader deployment or an associated capability claim.

## Recommended design direction and tradeoffs

Keep Flask, React and Agora. Rewriting in Next.js or adding several orchestration frameworks would not fix lifecycle ownership or missing policy enforcement. Extend the existing gateway boundary with six focused changes:

1. **Separate caller intent from provider state.** Durable session desired state, operation generation and provider status let end win over a late start. Retry/reconcile outside transactions. Adds a worker/lease but removes false terminal-state claims. Do not hold database/global locks over network IO.
2. **Make speech permission explicit.** An authenticated response-control boundary returns only current permitted directives; generation IDs invalidate obsolete output. If the pinned Agora integration cannot enforce this, that interface is a real blocker requiring a verified supported custom endpoint. Failures use constrained limitation messages, not unrestricted model fallback. Some generative flexibility and latency are traded for predictable control.
3. **Unify fact changes.** Speech and UI submit the same versioned confirmation/correction commands. Unknown confidence and unresolved fields are first-class states. Strong caller attribution cannot be guaranteed from a shared microphone: ambiguous confirmation requires repetition or human review.
4. **Treat human handoff as a transaction plus media workflow.** Snapshot and assignment are durable; accept, join and connected are distinct; post-accept corrections are amendments. Queue availability and transfer timeout are required deployment configuration, not model-generated promises.
5. **Use durable side-effect jobs.** Outbox/leases handle tickets, retries and reconciliation. This supports eventual consistency; it cannot manufacture exactly-once behavior from an external API without deduplication or lookup support.
6. **Generate views from observed state.** UI, voice messages and health probes use capability/participant/operation state. This prevents the current split between promised transfer and disabled controls. Shared typed contracts need initial work but reduce frontend/backend drift.

Suggested implementation order: L-01–L-04 and truthful shutdown/status first; then configuration/input/admission/capabilities and durable session foundation; then response control/confirmation; then transcripts/audio/languages; then handoff/ticket jobs; finally full failure/security/accessibility/capacity evaluation. Preserve Phase 0 compatibility checks from the existing implementation plan. Minimum console authorization precedes any human media access.

## Residual and intentional limits

Unclear speech, accents, overlap, network failure and probabilistic understanding can be mitigated, not eliminated. Calibrate on representative held-out synthetic/noisy Hindi-English fixtures; report errors by scenario rather than a single universal confidence number. A missing human cannot be fixed by software alone: staffing, queue ownership and fallback contacts require an operator decision. Account limits, model entitlement and TTS pronunciation require live evidence. Public-information answers need an approved maintained knowledge source; the current scope defaults to intake rather than inventing one.

PSTN, extra languages, production identity/scale, real personal data governance and professional advice are not automatically authorized by this review. Professional-advice boundaries remain intentional. Open-source denoisers/starter repos are candidates already assessed in [gap resolution](../technical/gap_resolution.md), not substitutes for domain control or permission to bypass Agora.
